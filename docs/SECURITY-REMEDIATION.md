# Security remediation — 17 November 2026

Scope: the security findings in `reports/investor-2026-11-16/ANNABID_PLATFORM_ANALYSIS.pdf`. The French PDF is preserved. This is a source-code remediation, not evidence that the deployed site has already been upgraded.

## Implemented controls

| Finding | Implementation |
| --- | --- |
| Login/registration abuse | Atomic PostgreSQL counters, shared across function instances; account and trusted-proxy IP limits; 429/Retry-After; nonblocking scrypt; monitoring events. Local counters are for development/testing only. |
| CSRF | Every API handler uses `secureRoute`: unsafe requests require an explicitly trusted Origin and reject cross-site Fetch Metadata. Checks live in the handler, independently of middleware. Cookies remain HttpOnly, Secure in production, SameSite=Lax. JSON APIs do not accept cross-origin form submissions. |
| Unrestricted image optimizer | Explicit HTTPS host allowlist, SVG optimization disabled, attachment disposition and sandboxed optimizer responses. |
| Vulnerable dependencies | Next.js 15.5.29 maintenance release, next-intl 4.15.1, patched PostCSS, Sharp and transitive overrides. Puck remains on 0.20.2; its vulnerable uuid dependency is upgraded rather than downgrading the editor. `npm audit` reports zero known vulnerabilities at implementation time. |
| Weak passwords | 12–128 characters, repeated-character rejection, HIBP Pwned Passwords range checks using only a five-character SHA-1 prefix and padded responses. Checks fail closed on network failure. All account creation/password-change paths use the policy. |
| Missing verification/recovery | Expiring, hashed, single-use email tokens; Resend delivery adapter; generic recovery response; verification before access; reset revokes all sessions and preserves MFA. No links or passwords in logs. |
| Missing admin MFA | Mandatory TOTP enrollment and verification. Password-only sessions cannot access admin APIs or pages. AES-256-GCM encrypted secrets; time-step replay prevention and attempt limits. Manual key entry works with standard authenticator apps. |
| Session lifetime/revocation | Hashed tokens only, 8-hour absolute lifetime, 1-hour idle timeout, 10-minute client rotation, maximum five devices, session list/revocation, global logout and password-change revocation. Legacy sessions are rejected. |
| Committed seed credentials | All seed hashes/salts disabled; seed generator creates non-authenticating records. Migration invalidates legacy sessions and disables the historical seeded admin. Administrator provisioning uses environment input and checks the password. |
| Diagnostic information leakage | Generic service errors with a request ID. Error codes stay in structured server logs; no SQL, connection strings or raw exception messages are sent to clients. |
| Untrusted upload MIME | Both upload paths check magic bytes, decode with bounded pixels, re-encode to WebP and strip metadata. Request streams are bounded even without Content-Length. New production uploads use Supabase object storage; old database-backed images remain readable. |
| Missing audit trail | Request ID, actor, action, time and outcome; redacted before/after changes inside PostgreSQL admin transactions; visual-editor revisions audited. Service role has SELECT/INSERT only on audit data. Local fixtures use append-only JSONL. |
| Missing browser headers | Nonce-based script CSP, object/base/form/frame restrictions, HSTS, COOP, CORP, existing MIME/referrer/permissions protections. Inline styles remain allowed because the visual editor uses React style attributes. COEP is intentionally omitted because Google Maps and external media do not supply compatible embedding headers. |
| Missing disclosure channel | `/.well-known/security.txt` publishes the configured monitored contact, languages and expiration. Missing contact returns 503 instead of publishing a fictitious address. |
| Data lifecycle/visibility | Reauthenticated account export/deletion, bounded token/session cleanup, 90-day audit retention and read-notification cleanup. Redacted monitoring webhook for failures and rate-limit events. |
| Regression coverage | Unit/route security tests, browser checks and a scheduled CI dependency audit. |

## Deployment steps (required before exposing the release)

1. Back up the database and restore it into a disposable database. Verify representative record counts and the ability to sign in using a newly provisioned test administrator. Never test restore by overwriting production. Recovery has not been tested against your hosted database in this workspace.
2. Run `npm ci`. Configure the real canonical `NEXT_PUBLIC_SITE_URL`, any additional exact `TRUSTED_ORIGINS`, and a 64-hex-character `AUTH_SECRET` generated from 32 random bytes. Store it in the deployment secret manager and back it up securely: losing it prevents decrypting MFA secrets. Never put secrets in a `NEXT_PUBLIC_` variable. A custom proxy must overwrite its client-IP header before enabling `TRUSTED_PROXY_IP_HEADER`; Vercel uses `x-vercel-forwarded-for`.
3. Configure a verified Resend sender (`RESEND_API_KEY`, `AUTH_EMAIL_FROM`), a monitored `SECURITY_CONTACT` and `SECURITY_ALERT_WEBHOOK_URL`/optional token. Verify actual mail delivery, expired links and monitored alert delivery on staging. No real messages were sent during the local tests.
4. Create a **public** Supabase Storage bucket for sanitized public images only; set `SUPABASE_URL`, server-only `SUPABASE_SERVICE_ROLE_KEY` and `MEDIA_BUCKET`. Do not use this bucket for identity documents or private attachments. The role must be limited to the intended bucket. New production uploads fail closed without this configuration. Existing bytea images remain accessible through their old routes.
5. Run `npm run security:migrate` against the intended database using a schema-owner connection. This changes security tables, signs out legacy sessions and disables the known seeded administrator password. It is deliberately separate from `db:migrate`, which imports seed records. Apply it before deployment to avoid rate-limit/audit-table failures.
6. Supply `ADMIN_EMAIL` and `ADMIN_PASSWORD` through the secret manager and run `npm run security:admin` for the administrator that should receive access. Verify the email and enroll TOTP on first login. Existing admin MFA is preserved. Only use `npm run security:admin -- --reset-mfa` after independently verifying the administrator's identity. This is the recovery path; there are no weak fallback codes or bypass accounts.
7. Deploy and verify every account flow. Existing accounts without a verification timestamp must verify email. All existing legacy sessions expire. Confirm CSP hydration, visual-editor saving, Maps, uploaded images, request-origin rejection and 429 responses on the deployed origin.
8. Schedule `npm run security:maintenance` daily using a separate maintenance/schema-owner connection. The application service role cannot delete audit records. Set alerts for job failure, `request_failed`, `auth.login.failed`, `auth.mfa.failed`, `rate_limit_exceeded`, and alert delivery failure. Archive audit records securely first if a longer approved retention period is required.

## Operational boundaries

- Rotate the historical administrator password in every environment and any reused credential. Removing the hash from the current tree cannot remove copies from Git history. Review access logs for past misuse. History rewriting is deliberately not performed.
- Run the application with a least-privileged database service role, not an owner/superuser: otherwise PostgreSQL grants cannot enforce append-only access. Keep the migration/retention identity separate. Existing RLS and TLS certificate checks remain enabled.
- Backups, database/storage encryption at rest, restore drills, mailbox monitoring, webhook alert routing and secret provisioning require the hosting accounts. The repository cannot prove those settings. MFA secrets are encrypted at the application layer; ordinary messages remain in the database and rely on database/storage encryption and access controls. This is not end-to-end encryption.
- No nonessential analytics cookies were added. Session cookies are necessary for login; local language preferences remain local. Update the public privacy notice to reflect actual processors, hosting region and approved retention policy before launch. Account deletion removes direct account data and authored messages, detaches memberships and preserves shared groups/activities with an anonymous creator. Restricted audit records expire after 90 days; backup copies age out under the hosting retention policy and must not resurrect deleted accounts after a restore.
- Strict per-response CSP nonces require dynamic HTML and private/no-store caching. This intentionally changes the CDN caching profile described in the report. Static assets remain cacheable. Measure the resulting capacity before growth; the full-snapshot data architecture in the separate scalability section is still a distinct engineering project.

Reference documentation: [Next.js CSP](https://nextjs.org/docs/app/guides/content-security-policy), [HIBP password range API](https://haveibeenpwned.com/API/v3#PwnedPasswords), [Next.js security advisories](https://github.com/vercel/next.js/security/advisories).
